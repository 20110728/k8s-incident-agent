# 有用证据 → 合理判断 → 稳定报告

基线：`feature/baseline-contracts` / `8489990`。每次只实施一个块，ECS 验收后再推进。本地只做静态检查。

## 已确认的问题

- Demo 将依赖连接、超时、HTTP 和响应校验失败压成 `False`，访问日志只有路径和状态，缺少区分原因的信息。
- 多轮在基线检索一次，补采后不重检索；活动证据原文每轮入模，重复探针日志和 JSON 嵌套转义增加输入。
- `unknown` 只允许 `insufficient_evidence` 领域；只修领域仍不能解决缺失证据、后续步骤为空的问题。当前兜底安全，但报告过于笼统。
- 历史 OOM 会进入检索查询；仓库没有依赖类 Runbook。具体排序原因、ECS 索引和旧单轮实际效果尚未验证。

当前链路：基线采集（不含日志/事件详情）→ 检索 → 模型选择补采/追问/诊断 → 程序检查引用、身份、事实和分类 → 合法报告或纠正；纯诊断语义错误耗尽后生成程序 unknown 报告。

## 三个独立验收块

| 块 | 修改范围 | 必须验证 |
| --- | --- | --- |
| 1 应用可观测性 | Demo 记录已有依赖请求的真实失败原因；补对应测试 | 最近 1000 行包含关键证据，实际模型输入收到证据，报告正确使用且不猜下游具体根因 |
| 2 模型输入表示 | 简单程序整理重复探针日志，减少 JSON 嵌套序列化 | 保存原文不变；次数、时间、异常原文、来源及行定位可追溯；无法识别的日志保留 |
| 3 报告鲁棒性 | 保守字段规范化、程序症状补充、针对性纠正、有用的 unknown | 不升级根因或置信度；保留有依据的解释；引用、身份、权限及存储错误不被兜底吞掉 |

块 1 已实施；2026-10-11 的真实导出确认关键依赖失败日志入模、两次调用形成合法依赖诊断，仍有措辞与覆盖范围限制。块 2 已实现、ECS 待验收，见 [第二块验收说明](acceptance/evidence-report-2.md)。块 3 尚未实施。检索先比较当前查询与当前事实优先的查询，不默认增加检索或模型调用。

## 边界与验收口径

- 保持最多 5 轮决策、6 次模型调用；不增加累计 token、时间、工具次数额度。
- 保持最近 1000 行/256 KiB 采样；保存证据、模型表示、页面预览、排障导出分开处理。
- 不新增跨资源访问、exec、任意网络请求或写权限；不改审批、身份、引用和恢复幂等。
- 不引入模型摘要、多 Agent、新数据库或复杂压缩；不将故障场景标签和操作者真值传给模型。
- 证据层通过与真实诊断有效分别记录。脚本 PASS 不代表模型有效；无关键证据时必须诚实说明未知和具体下一步。
- 每块交付修改文件、静态结果、ECS 命令及预期、部署要求和未验证项。首块详见 [验收说明](acceptance/evidence-report-1.md)。
