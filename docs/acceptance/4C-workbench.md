# 4C：事件工作台（待 ECS 验收）

事件列表/ID 找回、分页消息与采用标记、轮次切换、解释/比较、补充/调查/停止、版本绑定回答、人工说明及独立复查历史。复用诊断/审批/结果卡片；历史页不可审批，聊天不授权。显示证据/时间/用量，调试折叠；新观察不覆盖旧结论。工作台持续只读轮询，后端恢复后自动同步。

交互/回答提交前保存原请求编号；超时先 GET 找回，刷新不重发，显式重试也先查再以原编号提交。浏览器存储不可用时禁用这些提交。排队中的调查控制可跨刷新找回。服务端仍负责并发和权限校验。

```bash
cd ~/projects/k8s-incident-agent
git pull --ff-only origin feature/baseline-contracts
source .venv/bin/activate
bash scripts/accept_stage4c.sh
bash scripts/deploy_stage4c_frontend.sh
```

第一条脚本安装锁定的前端开发依赖、执行前端测试与构建、GET 检查已有 queued 事件及分页接口；不发模型/采集/写请求。预期 `PASS: 4C automated ECS acceptance`。可设 `STAGE4C_INCIDENT_ID` 选择已有事件；默认取列表第一项。失败提供 `evals/results/4c/<时间>/frontend.txt`、`api.txt`。

部署脚本从现有后端读取 kubeconfig 路径，补齐 Compose 插值，只重建 frontend。无新依赖版本、环境配置、数据库迁移；不需要重启 backend/worker。浏览器强制刷新后进行 L5 人工验收：

1. 从列表/ID 打开已有事件，刷新、关闭再打开，事件及已选轮次保留；历史页不能审批。点击更早消息/轮次/复查（有下一页时），不丢记录、不重复。
2. 解释已有结论，检查引用及时间；仅补充后显示“未核实”，继续调查后出现新轮次，旧轮结果保留。两轮比较不采集现场。
3. 出现追问时刷新后回答/跳过；等待中可停止，旧问题不能继续提交。无追问事件不强制制造生产故障，此项待合适测试事件验证。
4. 对已结束的测试事件填写人工说明，点“重新检查”；新观察与原结论分开，unknown/失败不显示成恢复。等待审批/执行/待核对时复查不可用。
5. 请求断网/超时后应显示待确认编号；恢复网络查询后找回同一任务，刷新不增加任务。可在测试事件操作，用浏览器开发工具断网；不要对真实修复做故障注入。
6. 无修复执行时重启后端，页面短暂同步失败后恢复，不能在状态失联时提交工作台操作。

自动 PASS 不代替浏览器验收。本地仅静态检查；实际构建、页面布局、浏览器断网/重启与真实模型交互仍待 ECS。阶段 5 未开始。
